### 🤖 我和 AI Agent 的协作方式

我不把 agent 当"高级补全"，把它当一个能自己跑起来、会查证据、会写结论的执行者。
分工是固定的：**它跑腿，我拍板。** 凡是需要判断边界的（要不要改线上、要不要动凭证），一律回到我手上。

```text
问题 / 需求
  └─→ Agent 侦察：读日志 · 翻仓库 · 开浏览器
        └─→ 证据不够？回到上一步，换条路再查
              └─→ 给方案 + 说清风险（含"要不要动线上/凭证"）
                    └─→ 我确认边界          ← 这一步一定有人
                          └─→ 改代码 · 跑验证
                                └─→ 真实环境复核 · 结论留痕
```

**几个真跑过的活儿**（都发生在这个仓库或它周边，不是 PPT）：

| 场景 | 我让 agent 做什么 | 结果 |
| :--- | :--- | :--- |
| CI 突然天天红 | 读 Actions 日志、判断是代码问题还是上游 API 变了 | 定位到 WakaTime 把 API Key 收紧成只写、读取必须换 OAuth Token |
| 加固失败路径 | 给流水线加一道凭证预检 | 从"跑两分钟甩一段 Python traceback"变成 5 秒内的可读中文报错 |
| 异步边界 | 发现接口返回 202 表示"统计还在算"，不是没数据 | 改成轮询等待，README 再没写出过半空的周报 |
| 浏览器里的琐事 | 让 agent 驱动真实浏览器改配置、审页面渲染 | 省掉手动点击，还顺手找出 3 个挂掉的外部组件 |

> 这套流程最值钱的不是"快"，是**每次翻车都能留下可复现的证据链**。下次同类问题，5 分钟能定位。
